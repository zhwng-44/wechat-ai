# 阿池：语音通话与声线方案

更新日期：2026-10-07

## 先说清楚现在能做什么

- 阿池已接入微信直聊，模型为 DeepSeek V4 Pro；Gateway 和微信通道已连接。
- 当前腾讯微信插件支持直聊和媒体，但没有实时电话能力。项目内已接入语音消息往返：本机 Whisper 转写，DeepSeek 生成文字，本机 Qwen Vivian 合成 WAV 附件。
- OpenClaw Talk 可以提供单独的浏览器/客户端语音对话，但实时浏览器 Talk 依赖受支持的语音服务；本机采用另建的本地浏览器语音客户端。
- 普通手机号电话需要 Voice Call 插件、Twilio/Telnyx/Plivo 等电话服务账号，以及公网可访问的 webhook；这也不是微信内电话。

微信内已接入的是语音消息往返，不是实时通话或原生语音气泡。Gateway 和语音服务已经重启加载改动；还需用户发一条真实语音确认附件投递。

## GitHub 声线候选

首选项目：[QwenLM/Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS)。官方仓库支持中文语音，也提供固定中文女声与文字描述设计声线的能力。

**第一候选：Vivian。** 官方仓库描述为明亮、略带锋芒的年轻女声，和阿池“平静里带刺、偶尔冷幽默”的方向接近。次选 Serena 更温和柔软。最终仍应试听实际音频再决定。

Qwen 官方提供 [ModelScope 在线体验](https://modelscope.cn/studios/Qwen/Qwen3-TTS)。如果要从文字设计阿池自己的声线，可以试听 1.7B VoiceDesign；如果采用本机模型，要先核对 Windows 依赖与 RTX 4060 Laptop 8 GB 显存余量，再决定使用 0.6B 还是 1.7B。

声线设计提示词：

> 普通话女性中低音，清晰自然，略微低沉但不沙哑。语气平静、直接，带一点克制的冷幽默；句子短，停顿自然，偶尔轻轻挖苦事情，但不攻击听者。不要夹子音、撒娇、播音腔或客服腔。遇到对方难过时，放轻声音，认真、简短地回应。

试听台词：

> 嗯，我听着。你先说重点，省得这件事又被你讲成连续剧。

Qwen3-TTS 官方仓库使用 Apache-2.0 许可。声音合成留在本机并不代表聊天也完全本地；当前 DeepSeek 对话模型仍会收到用于生成回复的对话内容。

## 可选路线

1. **微信语音消息往返**：已将插件接到本机 Whisper + DeepSeek agent + 本机 Qwen3-TTS。语音输入在本机转写；回复以文字和 WAV 文件附件发回。服务已重启加载改动，需在微信确认附件投递。
2. **本地浏览器语音客户端**：另有 `local-voice/` 独立语音界面，支持半双工连续麦克风交互；它不嵌入微信。
3. **普通手机号通话**：装 Voice Call 插件并配置电话服务账号、号码与公网 webhook；要确认地区、资费和密钥。
4. **全离线对话**：还要把文本模型也迁到本机；目前聊天文本仍交给 DeepSeek 云端。

## 当前进度

- 已完成：OpenClaw、阿池人设、分层记忆、微信扫码授权、DeepSeek API Key 本地认证、默认模型 DeepSeek V4 Pro。
- Gateway 当前可连接，微信通道状态为 running。
- DeepSeek 官方 API 提供文本与图像接口；没有语音识别或语音合成接口。因此它不能直接当声学引擎。当前选用“本机 Whisper 识别 + DeepSeek 对话 + 本机 Qwen3-TTS Vivian 合成”。对话文字仍会发送到 DeepSeek 云端；原始音频与合成音频留在本机。
- 已新增并运行 `local-voice/` 独立浏览器语音客户端，监听地址固定为 `127.0.0.1`，复用 `achi` agent 和 DeepSeek 默认模型。本机闭环已成功；原始浏览器录音不写盘。
- 已修改项目内安装的 `@tencent-weixin/openclaw-weixin` 2.4.9：微信语音缺少平台转写时调用本机 Whisper；语音消息触发的回复由本机 Vivian 生成 WAV 附件。Gateway 与语音服务已重启加载改动，仍需用户发送微信语音完成实际客户端确认。
- 微信 iLink 插件将一般音频 MIME 作为文件附件；官方插件仓库反馈原生 VOICE 消息在客户端不可见或不可靠，因此当前不宣称支持原生语音气泡。
- 连续麦克风通话通过独立本地浏览器页面完成。微信内实时通话仍不受当前通道支持。
