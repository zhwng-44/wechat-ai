## 使用本地语音通话

语音服务已在运行时，打开 [阿池本地语音页面](http://127.0.0.1:18790)，点击“开始通话”，并允许页面使用麦克风。第一次实际使用还需要你在浏览器里完成麦克风授权。

如果服务已经停止，在项目目录运行 `start-local-voice.cmd` 并保持窗口运行，再打开上面的页面。点击“挂断”结束通话；需要关闭服务时，在启动窗口按 Ctrl+C。

通话采用半双工：你停顿后阿池回答，播放结束后继续听。页面只监听本机回环地址，不向局域网或公网开放。

## 在微信里语音聊天

给阿池发送一条微信语音消息。若微信消息带有转写文字，插件直接用该文字；若没有，项目内的微信插件调用本机 Whisper 转写。阿池通过 DeepSeek 生成回复，再由本机 Qwen Vivian 合成 WAV 文件，与文字一起作为附件发回。当前 Gateway 和本地语音服务已启动；使用时请保持两者运行。

这会发送普通 WAV 文件附件；当前插件/微信 iLink 通道不保证显示原生语音条，也不提供微信内实时电话。用户语音原始音频只交给本机 Whisper；转写文字会发送给 DeepSeek；阿池合成的 WAV 会通过微信发送给你。

## 语音和数据流

- 原始录音发给本机 Whisper 转成文字。
- 转写文字进入 `achi` agent，由 DeepSeek 生成回复。
- Qwen3-TTS Vivian 在本机把回复合成为语音。
- 原始录音和合成音频不上传语音云服务；对话文字会发送给 DeepSeek。

## 微信与语音的区别

微信文字直聊通道已连接。语音消息现在走本机转写与合成，阿池会回复文字和 WAV 附件；连续麦克风通话仍通过独立本地浏览器页面完成，不在微信聊天窗口内。

## 修改阿池

- 修改性格：编辑 `workspace/SOUL.md`。
- 维护关于你的长期记忆：编辑 `workspace/USER.md` 和 `workspace/MEMORY.md`。
- 检查微信连接：在项目目录运行 `oc.cmd channels status --probe`。
- 检查 Gateway：运行 `oc.cmd gateway status`。

## 诊断备注

本机 `achi` agent 和本地语音 API 已成功调用 DeepSeek。最近一次 Gateway 深度检查提示 DeepSeek provider 插件比预期版本落后一版，且 ClawHub 暂时不可达；这不影响刚验证通过的本地语音闭环。若微信之后不回复，再检查 Gateway 和插件状态。

请勿把 API Key 或登录设备码发到聊天里。之前输入到普通 PowerShell 命令行的 Key 已按建议作废。
